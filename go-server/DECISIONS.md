# Port decisions

Answers to every ambiguity the behavioural specs raised about the Node server. Porters follow
these without re-deciding; reviewers check against them. The rule behind them:

> **Anything a shipped client or the database can observe on a success path is reproduced
> exactly. Latent bugs that no client relies on are fixed, and every fix is listed here.**

"Node" below means `server/src` as it was before the Node server was removed from the repository
(8 Sep 2026; `git log -- server/`, last commit carrying it `c19963b`). "Deviation" means the Go
server behaves differently from Node on purpose.

## 1. Wire format

| Topic | Decision |
|---|---|
| JSON key order | Not required. Field *sets*, names, types and null/absent/empty rules are required. Go structs give a stable order anyway. |
| Duplicate consecutive `room:state` | Not required to match in count. The final snapshot must match. The parity harness collapses consecutive identical `room:state` per viewer. |
| Join-side event order (`room:state` before `room:joined`, leaver's traffic before `room:left`, mover's `room:closed` before `room:moved`/`room:joined`) | **Reproduce exactly.** Flutter's screen switching depends on `room:closed` never arriving *after* the new `room:joined`. |
| Spurious `game:turn` for an asker who leaves during a pending sideshow | Either behaviour is acceptable; not asserted. Port the Node sequence and let it fall out. |
| Long polling | **Deviation.** Not implemented. `transport=polling` gets HTTP 400 `{"code":0,"message":"Transport unknown"}`. Every shipped client is websocket-only or websocket-first without fallback. |
| `/socket.io/socket.io.js` | Served by the Go server from an embedded copy of the socket.io client bundle (`internal/app/assets/socket.io.min.js` + its MIT `LICENSE`, copied from the former `server/node_modules/socket.io/client-dist/socket.io.min.js`), so the browser reference client works unchanged. `.min.js` also served. |
| Engine.IO `sid` | Opaque 20-char base64url id; alphabet need not match `base64id`. |
| `?token=` query on the handshake | Kept (Node accepts `handshake.query.token`). |
| Handshake failure message | **Deviation.** Always the auth code (`missing_token`, `invalid_session`, `unknown_user`, `unauthorized`). A database error during `findById` is `unauthorized`, never a SQLSTATE. |
| Unknown inbound event | Never acked (same as Node). Malformed packet closes the connection. |
| `REDIS_URL` | Read, logged as ignored. No adapter. |

## 2. Rules engine

| Topic | Decision |
|---|---|
| Ladder first rung `min(base, perBetCeiling)` | Reproduce (the tests exercise it). |
| Config keys Node leaves undefined to disable a feature (`maxBlindMoves`, `maxMissedTurns`, `sideshowMinPlayers`, `sideshowTimeoutMs`) | In Go, **0 means disabled/never triggers** for those four, and 0 means **unlimited** for `MaxBetRounds`, `PotLimitMultiplier`, `MaxRaiseSteps`, `MaxPot`. RoomManager always sets every field explicitly. Go unit tests pass explicit values. |
| Settle retry hitting `duplicate_action` | **Deviation.** Treated as success (the write already landed). Retries recompute `version` from the live table and resend the original snapshot, as Node does. |
| `_startRefused` when the unfunded user is not seated | Same as Node: no retry timer; the next add/remove restarts the table. |
| `pickWinner` in handRank | Ported (exported, unit-tested), Table keeps its own tie loop as Node does. Both must agree; a test checks that. |
| Boot refusal for errors other than `insufficient_chips` | Same as Node: retry every `nextHandDelayMs`. |
| `collectBoot` statement order (pots row after wallet updates) | Same as Node. |
| Lock ordering of wallets | Byte-wise ascending user id (ids are ASCII uuids). |
| Missing-key semantics of `balances` | Key presence, never truthiness. A balance of 0 is valid. |
| Settle retry pending when the table is destroyed (last player leaves, consolidation, sweep, shutdown) | **Deviation (money).** Node's retry callback returned on `_destroyed` and the pot was never banked. Go continues the idempotent write off the actor (`Table.settleDetached`, same back-off and 10-attempt cap, no Listener events); `RoomManager.Shutdown` waits for it within its budget and `destroyTable` logs the outcome (`Table.WaitSettlements`). |
| `settle` statement order | **Moot since 9 Sep 2026** — the `hands` table is gone, so there is no second statement to order against. Kept as the record: the Go port locked wallets (ascending) before `INSERT INTO hands`, where Node inserted the hands row first and its `winner_id` FK took a KEY SHARE on the winner's row out of order, which could deadlock against another table's boot collection (`db/review_money_test.go`). Settlement now locks wallets in ascending id order and writes nothing else. |
| Force Sideshow — `game:action {action:"forceSideshow", actionId?}` | **Deviation (owner, 13 Sep 2026).** Node had no such action. A sideshow without the request and the answer, paid for with one hammer (`users.hammer`, 20 per account). Eligibility is exactly `sideshowBlockedReason` (same codes, messages, order and neighbour) and it is the turn's one ask. It resolves inside the move through the accepted-sideshow code (`settleSideshow`), with reason `forced`: `game:sideshowReveal {reveal:{reason:"forced", packedUserId, hands}}` to the two players only, `game:sideshowResolved {fromUserId, toUserId, accepted:true, reason:"forced", packedUserId}` to the room, no `game:sideshowRequested` and no `room:state.sideshow`. The hammer is spent BEFORE anything resolves, on the actor, through `TableOptions.Hammers` (`game.HammerWallet`; `db.Hammers` → `hammer_spends`, key `<handId>:force:<userId>:<actionId>`): `no_hammers` or `persist_failed` leave the table unchanged; a committed spend whose answer was lost is not charged again on retry; an id the hand already delivered is refused `duplicate_action` before the wallet is asked, so one hammer buys one forced sideshow. Ack `{ok:true, action:"forceSideshow", toUserId, packedUserId, hammers}` (hammers = left). `you.options` / `game:yourTurn.options` gain `canForceSideshow` (equal to `canSideshow`; the hammer count is the client's to check). No chips move and nothing touches `chip_ledger`. Metrics: `moves_total{action="forceSideshow"}`, `invalid_moves_total{code="no_hammers"}`, `db_transaction_duration_seconds{op="hammer_spend"}`. |
| Missile — `game:action {action:"missile", actionId?}` | **Deviation (owner, 14 Sep 2026).** Node had no such action. The player on turn pays one missile (`users.missile`) and every hand still in the hand is shown at once, the best taking the pot. Refusals, in order: `no_hand`, `not_in_hand`, `not_your_turn` (the usual `_act` checks), `sideshow_pending`, `too_few_players` "A missile needs at least 3 players in the hand" (fewer than `game.MissileMinPlayers` = 3 active players, the firer included — the sideshow's code with a message of its own), `insufficient_chips` "You need enough chips for a show to fire a missile" (the firer holds less than `Table.showCost`, the chaal a show would charge them — owner, 14 Sep 2026; nothing is charged for it, and exactly the price is enough), `duplicate_action` for an id the hand already delivered, then the spend: `no_missiles` "You need a missile to fire" or `persist_failed`. Every refusal leaves the table exactly as it was. Blind and seen players may both fire. The missile is spent BEFORE anything resolves, on the actor, through `TableOptions.Missiles` (`game.MissileWallet`; `db.Missiles` → `missile_spends`, key `<handId>:missile:<userId>:<actionId>`), so a retried spend whose answer was lost is not charged again. Then `game:action {userId, action:"missile", amount:0, pot, stake}` to the room, and the hand resolves through `resolveShowdown` with the new win reason `missile` — `game:showdown {reveals, reason:"missile"}` then `game:handEnded {…, reason:"missile"}`, with the settlement and ledger rows of any showdown. The firer takes the show payer's place in the tie order: an exact tie goes against them. `handEnded.nextHandAt` and the countdown's `startsAt` are now + `NEXT_HAND_DELAY_MS` + `MISSILE_REVEAL_EXTRA_MS` (Go-only key, default 3000; `Table.holdStartUntil`, spent by the next countdown) so the client can play the flight and everyone can read the hands. Ack `{ok:true, action:"missile", missiles}` (missiles left, present at 0). `room:state.you` gains `canMissile` (always present), repeated in `you.options` / `game:yourTurn.options` beside `canForceSideshow`; it says nothing about the missile count. Metrics: `moves_total{action="missile"}`, `invalid_moves_total{code="no_missiles"}`, `games_completed_total{reason="missile"}`, `db_transaction_duration_seconds{op="missile_spend"}`. |
| Client `actionId` containing `:` | **Deviation (money).** Dropped (fresh uuid) in the socket layer and again in `Table.chargeToPot`. Every server-generated `chip_ledger.action_id` is colon-separated and `<userId>:milestone:<n>` fits in 64 chars, so Node let one player pre-occupy another's milestone key with a bet and block that reward for good. Real clients send uuids / plain tokens. |
| Variation Teen Patti — category `variation`, `game:selectVariation {variation}`, `game:variationSelecting`, `game:variationSelected` | **Deviation (owner, 18 Sep 2026).** Node had two categories and one ranking. A third category, `variation`, is a seen table in every rule `config.TableRules` composes (the `SEEN_*` keys ARE its rules; there are no `VARIATION_*` twins) whose every hand opens with a **window**: the hand is dealt as always, then instead of `setTurn(firstSeat)` the table calls `beginVariation(firstSeat, undealt[0])` and the player to the dealer's left has `VARIATION_SELECT_TIMEOUT_MS` (Go-only key, 10000; 0 = the window never lapses, as `SideshowTimeout` 0 means of a sideshow) to choose one of `MUFLIS`, `AK47`, `JOKER`, `HUKAM`, `LOWEST_JOKER`, `HIGHEST_JOKER` — the canonical wire values, matched EXACTLY by `game.ParseVariation` (no trimming, no case folding, no aliases). While the window is open **nobody is on turn** (`hand.turnSeat` stays -1, the turn clock is not running, `you.options` is null) and `Table.Act` refuses every action but `see` with `variation_pending` "The variation is still being chosen" — `see` stays free, so the chooser may look at their cards first. The window closes exactly once, in `closeVariation`, by one of three closures on the table's actor: the chooser's `SelectVariation` (`selectedBy:"PLAYER"`), the window's timer (`"TIMEOUT"`, the server chooses `VariationDefault` = MUFLIS), or the chooser leaving the table (`"LEFT"`, MUFLIS, and the turn opens with the next player through `advanceTurn` exactly as if they had been on turn and left). Because all three are closures posted to one goroutine they run one after another, never together, and `closeVariation` does nothing unless `window.open` — so a pick and a timeout arriving in the same instant choose once: whichever the actor runs first wins and the other finds the window closed. There is no lock and no compare-and-swap because there is no second thread; it is the guarantee `hand.turnToken` and the sideshow's pointer check already give the two older clocks. The deadline is the server's even in the instant before its timer's closure runs: a `SelectVariation` that reaches the actor at or past `deadline` makes the server's choice happen now and is refused `variation_expired`. Closing gives the chooser an ordinary FRESH turn with a full clock (letting the window lapse is not a missed turn). `SelectVariation` refusals, in order: `no_hand`, `not_seated`, `no_variation` "This table does not play variations" (the hand has no window), `variation_already_selected` (closed, however it closed — a second tap included), `not_selecting` "It is not your turn to choose the variation", `invalid_variation`, `variation_expired`; the socket layer adds `not_in_room` first and takes the player from the socket's session, never the payload (`game:selectVariation` carries no player id; any non-string `variation` decodes to "" and is refused `invalid_variation`). Ack `{ok:true, variation, selectedBy, turnUp?}`. Refusals of this event also feed `invalid_moves_total{code}`. **One ranking, not seven** (`game/variation.go`): every variation but Muflis is classic Teen Patti with some cards wild and Muflis is classic Teen Patti compared the other way round (`Compare(b, a)`; the ace stays high, so 5-3-2 off-suit is the best hand and a trail of aces the worst). `VariationRules{Variation, WildRank, WildSuit}` — whose ZERO VALUE is classic, which is what a seen or blind table holds — carries a wild rule and a comparison direction; `evaluateWithWilds` scores a hand as the best classic hand its wild cards can complete by SEARCHING: each wild may stand for any card of the deck that is not a natural card of the same hand, no two for the same card, every candidate goes to the one `Evaluate`, the strongest wins (≤ 50 evaluations for one wild, 1,275 for two; three wilds are answered from a constant, a trail of aces, which a test holds to the exhaustive search). AK47: every A, K, 4, 7. JOKER: the RANK of the card turned up from the undealt deck. HUKAM: that card's SUIT (a wild "trump" suit — the brief said "trump/wild"; it is isolated in `EvaluateHukam` so a true trump rule could replace it). LOWEST_JOKER / HIGHEST_JOKER: per hand, the lowest / highest rank it holds and every duplicate of it (a trail is three wild cards); the ace is high. The turned-up card is `Deal`'s own `remaining[0]` — drawn from the same shuffled deck the hands came from, so it is in nobody's hand — kept on the hand for every variation deal and put on the wire (`turnUp`) ONLY once JOKER or HUKAM has been chosen. Both comparison sites use the hand's rules: `resolveShowdown` (show, forced showdown, pot limit, missile) and `settleSideshow` (sideshow, Force Sideshow). Exact ties are unchanged (the show-payer / missile firer loses, else nearest the dealer's left; a sideshow's asker loses). Wire additions, all ABSENT on a seen or blind table so those payloads are byte for byte what they were: `room:state.variation {selecting, userId, displayName, seatIndex, startedAt, deadline, timeoutMs, options, selected, selectedBy, turnUp?}` (public, identical for every viewer, and everything a reconnecting client has); `game:showdown` and `game:handEnded` gain `variation` and `turnUp`; each reveal and each sideshow-reveal hand gains `wild` (which of its cards played wild — `handName`/`category` are what the hand MADE). **Live store:** the window is `SnapshotHand.variation` (the turned-up card included, always — the snapshot never reaches a client) and `SnapshotConfig.variationSelectTimeoutMs`; `resumeTimers` re-arms the window for what is LEFT of the original deadline, or closes it at once (TIMEOUT) if that passed while the process was down, and must run before the "no turn recorded → open play" branch, which would otherwise start betting behind the chooser's back. `endHand`, `destroy`, `suspend` and `fence` stop the window's timer. **The category set is closed at three and normalised in three places that must agree** — `config.NormalizeCategory`, `game.NormalizeCategory` and `NewTable` (which is also where a table restored from the live store gets its category back): anything unrecognised is still seen, so a client cannot name a fourth, and a near miss (`Variation`, ` variation`) is a seen table, never a window by accident. `LobbyOptions.categories` is `[seen, blind]` plus `variation` only when the menu offers a variation entry (or is empty = any pair), so a deployment that has not listed one tells its clients exactly what it always did; the default menu now ends with `variation:200`. A variation table is given `VariationSelectTimeout`; a seen or blind table's `TableConfig` and snapshot are unchanged. Metrics: `games_*_total{category="variation"}`, `socket_messages_total{event="game:selectVariation"}`, the six new codes in `KnownErrorCodes`. **Rollout:** an installed app older than the build that knows the category draws the card as a seen table and never shows the picker, so every hand there is a server-chosen Muflis — raise `MIN_CLIENT_BUILD` to that build before listing `variation:` in production's `LOBBY_TABLES`. A Go tag that predates this cannot boot on a `.env` that lists it (`parseLobbyTables`), and rewrites a variation table restored from Redis to seen. **Changed later on 18 Sep 2026 (owner):** (1) *stacks are hidden* — "keep the same thing as blind table that no one can see other player amount": `Category.HidesChips()` is true for blind AND variation, so a variation table takes its betting from seen and its secrecy from blind; (2) *no pot limit* — "in all variation table, do not keep any pot limit": `VARIATION_MAX_POT_BOOTS` (Go only, default 0 = uncapped) replaces the seen table's fixed 20 Lakh for this category, and is a count of the table's own boots because a fixed figure cannot fit several stakes (20 Lakh is two boots at the 10 Lakh table — every hand would end at the deal); `MenuMaxPot(category, boot)` advertises what `TableRules` gives; an overflowing product stops the boot; a private variation table keeps `PRIVATE_MAX_POT`; (3) *two tables only* — "in variation keep only two tables 50000 and 10Lakh": the default menu's variation entries are `variation:50000:max=1000000000,variation:1000000:min=500000000`, behind blind's bands for those stakes; (4) *`you.hand`* — `{handName, category, wild, playsAs}`, the viewer's own seen cards as the variation counts them (`EvaluatedHand.PlaysAs`: each wild card replaced by the stand-in the search chose, index for index), sent in `you` alone once they have looked and the variation is chosen, so the client can turn the wild cards into what they played as; absent everywhere else, so seen and blind snapshots are byte for byte unchanged. **5-Card Teen Patti (owner, 18 Sep 2026):** a seventh variation, wire value `FIVE_CARD`, appended LAST. Every player holds five cards and plays the best three, found by the server (`EvaluateBest`: the maximum, by the one classic `Compare`, of the C(5,3)=10 hands the one classic `Evaluate` scores — no second ranking). The brief asked for "deal 5 cards to every player" once it is selected, and the existing flow deals BEFORE the window; rather than move the window ahead of the deal (which would change `see`-during-the-window, the deal animation and every window test), **every hand is still dealt three and FIVE_CARD tops each hand up to five from the same shuffled deck** — statistically the same deal. The two top-up cards per player are drawn AT the deal (`drawExtraCards`, after the turned-up card, round the table in deal order) and held server-side in `variationWindow.extra` / `SnapshotVariation.Extra`, so a restart mid-window deals the same cards and the choice cannot influence them; they are dealt by `closeVariation` → `dealExtraCards` and dropped otherwise. `Variation.CardsPerPlayer()` is the single source of the hand size; `variation.cardsPerPlayer` on the wire is the server's statement of it. A hand whose deck could not cover the top-up (more players than any lobby table seats) does not offer FIVE_CARD and refuses it as `invalid_variation`. |

| Everybody folding at a dealer game | **Decided 19 Sep 2026, from the rule in `flow_threecard.go`.** At 3-Card Poker a fold is a move against the HOUSE, not against the other players, so all of them folding is an ordinary outcome and each fold costs its ante. The generic "nobody is left in the hand" branch refunds the pot, which is right where players play each other (a pot nobody can win must go back) and wrong here: it made folding free whenever the whole table folded, and kept in the economy chips the rule takes out of it. `resolveIfOnlyOneLeft` therefore resolves against the dealer when the variant has one. |
| A checkpoint the ledger refuses | **Deviation from the Teen Patti engine (19 Sep 2026), in the poker rooms only.** A checkpoint has no retry chain — only the hand-end settle has one — and the settle SKIPS a player who left mid-hand, because their stake was banked by their own `hand_left` row. When that row was refused, nothing ever wrote it: the leaver's stake stayed unbanked while the winner was paid a pot that included it, and the books gained chips. Whatever is still owed therefore rides the SETTLE REQUEST itself, as a money-only row (`Outcome: false` — the counters were the leave's to move) under the settle action id, so the Settler's retry chain carries it until it lands. A first version of this fix wrote the catch-up as a one-shot `Checkpoint` under the leave's own action id; an adversarial review proved that insufficient — a ledger outage spanning both the leave and the hand end left the money unwritten for good, because a checkpoint is exactly the thing with no retry. The settle action id is used rather than the leave's for two reasons: the leave's may already be spent (a write that landed unheard), and `chip_ledger`'s audit requires a `hand_left` row to carry the `:left:` id, so a catch-up row is written as `hand_loss`. The residual hazard is the one the packed path has always had: a write that committed but whose acknowledgement was lost leaves `chipsWritten` stale, and the catch-up then moves the money a second time. `internal/game/table.go` has the same skip and the same hole in its broader form — no catch-up at all, so ONE refused write suffices — pre-existing since Node; it is left alone pending the owner's call rather than changing Teen Patti's money path unasked. |
| A room destroyed with a hand live | **Decided 19 Sep 2026.** `endHandRefunded` gives every stake back to the seat that put it in, EXCEPT to a player who had already left: their stake stayed in the pot when they walked out (CLAUDE.md §5.1) and their wallet was written through at their own checkpoint. Crediting them moved chips no seat held and, because their leave had spent the only action id that row could carry, the write was refused as a duplicate and the money vanished from the books. |
| A 3-Card Poker tie | **Decided 19 Sep 2026.** A push returns both bets, so it is neither a win nor a loss: `SettleEntry.Push` (new, never set by Teen Patti) suppresses `hands_won`, `hands_lost`, `total_winnings` and `biggest_pot`, leaving `hands_played` alone to move. Booking it as a win — which it was, because a push shares the "pay this player" path with a win — grew a player's lifetime winnings by a stake that had merely been handed back. |
| An ante is collected, a blind is not | **Decided 19 Sep 2026.** A blind is a bet ON the first street and stays in front of the player; an ante is collected into the pot before the deal and is part of no street's bet. Leaving it in `seat.streetBet` made 5-Card Draw's first street open with every seat already matched, so the minimum bet the server advertised — and accepted — moved no chips at all. |
| A seat that folds mid-street | **Decided 19 Sep 2026.** Its street bet is cleared with everyone else's when the street ends: those chips were collected into the pot. Keeping the figure drew a bet in front of a packed seat for the rest of the hand and made `potsNow` subtract it a second time, so `poker.pots` came out short of the `pot` in the same snapshot. |
| 3-Card Poker's `poker:handEnded.pot` | **Decided 19 Sep 2026.** It is what was STAKED, as `events.go` documents ("everything that was on the table") and as every other variant reports. `resolveDealer` used to draw the pot down as the house paid, so a hand of 800 was announced with a pot of 0. The payouts travel in `pots[].winners` and `reveals[].won`. |
| Poker hides the other stacks | **Decided 19 Sep 2026 (owner: "in poker do not show opponent chips").** `Category.HidesChips()` is true for the four poker categories, as it already was for blind and variation, so a poker snapshot carries `chipsHidden:true` and every `seats[].chips` but the viewer's own is `null` — never 0, so a client cannot draw a withheld stack as a figure. The brief had called poker's stacks public; the owner's instruction supersedes it. |
| No all-in move | **Decided 19 Sep 2026 (owner: "remove the option ALL in one button").** `ActionAllIn` is refused, `applyAllIn` is gone and `Options` no longer carries `allIn`/`allInAmount`. Nothing is lost, because every amount the server offers is already capped at the player's stack: the maximum bet or raise IS the shove, a call short of the current bet is the all-in call (`CallAmount = min(toCall, chips)`), and a stack smaller than the minimum bet is offered that stack as its minimum. The boolean `allIn` on a seat, an ActResult and a `poker:action` event — which marks a move that put the last chip in — is a different thing and stays. |
| The Poker family — categories `three_card_poker`, `five_card_draw`, `texas_holdem`, `omaha`; `poker:action`; the nine `poker:*` events; `room:state.game` / `.poker` | **Deviation (owner, 19 Sep 2026; `POKER_PLAN.md`, CLAUDE.md §6.5).** Node had one game. The poker rooms are a SECOND family in the same RoomManager, lobby, socket layer, live store and ledger: `game.Room` is the interface the manager holds, `*game.Table` implements it unchanged in behaviour, `*poker.Table` implements it on the same shell (`game.Actor` / `LiveState` / `Settler`, extracted from `Table` without changing what it does — the race suite and 195/217 parity, with the four documented failures, say so). Rules that are the brief's, not Node's, and were decided as follows: **(1) the stake is the LOBBY_TABLES boot** — the big blind at Hold'em/Omaha (small blind = half, integer division) and the ante at 3-Card Poker / 5-Card Draw — so `TABLE_STAKES`, the menu, the lobby card and the ledger keep one figure; **(2) the buy-in is `POKER_MIN_BUYIN_BOOTS` × boot** (10 by default), enforced where Teen Patti enforces "chips ≥ boot" (the join, the deal, the unfunded grace) and advertised as the menu's `minChips`; **(3) 3-Card Poker has no house wallet** — chips a player wins enter the economy and chips they lose leave it, like a reward or a picture purchase, recorded as ordinary `hand_win`/`hand_loss` rows whose `delta` may be positive on a `hand_win` with nobody's `hand_loss` to match; the money audit exempts `variant='three_card_poker'` from the per-hand zero-sum and nothing else, which is the whole reason `chip_ledger.game`/`variant` exist (nullable; NULL on every Teen Patti row); no ante bonus, no pair-plus; **(4) the dealer qualifies with queen-high or better** (the brief's rule; a non-qualifying dealer pays the ante 1:1 and returns the play bet); **(5) bets are TO an amount** (`raise` names the player's whole street bet after it, `minRaise` is the last raise size and never less than the big blind), `allIn` is a distinct action so a short stack is never refused for an amount it cannot make; **(6) odd chips go clockwise from the button's left** (`Award`), the button last; **(7) a fold is the pack checkpoint, a leave the left one, the hand end the settle** — nothing new in `Checkpoint`/`Settle` beyond the two labels; **(8) a new street emits `room:state`** (the only snapshot a reconnecting client has must carry the board and the options); **(9) `wrong_game`** is the answer to a `game:*` move at a poker room and to `poker:action` at a Teen Patti table, before any rule runs; **(10) the timeout on a betting street folds** (checks where a check is free), counts a missed turn and kicks at `MAX_MISSED_TURNS`, as Teen Patti's does. Everything a Teen Patti client or the database could observe is unchanged: `game`/`poker` appear only on a poker room's snapshot, the events are all new names, the ledger columns are NULL on every Teen Patti row, the metrics reuse `games_*{category}` / `moves_total{action}` / `invalid_moves_total{code}` with new label VALUES only. **The menu is one table per game, all four at 50,000** (owner, later on 19 Sep 2026: "in poker category only keep one table 50000 for each gameplay"; it was six entries at 200 and 5,000). Consequence, stated rather than worked around: the buy-in is `POKER_MIN_BUYIN_BOOTS` × 50,000 = **5,00,000** at every poker table, more than the 3,00,000 welcome, so a brand-new account sees the whole Poker category shut until it has won 5 Lakh — the same kind of gate the 10 Lakh variation table already has (50 Crore). `POKER_MIN_BUYIN_BOOTS` is the one key that opens them to a new player without changing the stake, and the buy-in minimum was kept rather than lowered because 10 big blinds is already the shallowest stack that plays poker sensibly. **Rollout:** an installed app older than the first poker-aware build draws each poker card as a seen table; raise `MIN_CLIENT_BUILD` before listing a poker entry in production's `LOBBY_TABLES`; a Go tag older than this cannot boot on such a `.env` (`parseLobbyTables`), and cannot restore a poker room's Redis snapshot: it reads every `kt:table:*` document as a Teen Patti one and its validator never looks at `category`, so the poker snapshot keeps its config under **`pokerConfig`**, not `config`, and that tag's first check (`config.maxPlayers > 0`) refuses it — "snapshot has no config" — and `dropStored` deletes it; the room is gone and its players re-join (the wallet is what PostgreSQL last knew, CLAUDE.md §5.1) rather than finding themselves at a SEEN table built from poker seats. `TestAPokerSnapshotHasNoConfigKey` pins the key. |

## 3. RoomManager

| Topic | Decision |
|---|---|
| Rooms of two games in one manager (19 Sep 2026) | `RoomManager.tables` is `map[string]game.Room`; every method that took `*Table` takes or returns `Room`; `RoomManagerOptions.Factories[game.Game]` opens and restores rooms (`poker.Factory` for `GamePoker`; Teen Patti's is built in). `quickJoin`/`switch` match on category + boot as before, so a poker seeker never lands at a Teen Patti table. `LobbyOptions.categories` lists a poker category only when the menu offers it; `options.tables[]` entries of a poker table carry `game`, `smallBlind`, `bigBlind`, `ante`, `minBuyIn`, `holeCards`, `maxDiscards` and a `minChips` raised to the buy-in. The sweeper, consolidation, the seat-lock stripes, `WhileUnseated` and the settlement `owed`/`departing` counts work over `Room` and are family-blind. |
| `room:create {isPrivate:false}` (public table at any boot, no chips check) | **Deviation (security).** A public create is validated like `quickJoin`: `invalid_stake`, `table_not_offered`, `insufficient_chips`, `over_entry_cap`, then the table's stack band (`below_table_minimum` / `over_entry_cap`), in that order — every check, and the seat, made by `RoomManager.CreateAndJoin` under the creator's seat lock on the wallet read under it. Private create is unchanged (boot forced to `privateBoot`). |
| `room:create` by a seated player | **Deviation.** `already_in_room` is checked *before* any table is created. No orphan table. |
| `switchTable` failure after leaving | **Deviation.** The seat on the source table is restored (as `_movePlayer` does). If the source is gone, the player gets `room:left` and the error. |
| `switchTable` target | **Deviation (owner, 25 Sep 2026; replaces the 13 Sep random pick).** Node sent a switcher to the FULLEST other public non-full table of the same boot and category, and refused with `no_other_table` when there was none. Go sends them to the one with the FEWEST players (`pickEmptiestTableLocked`, seats taken plus seats held; ties drawn with crypto/rand, keeping the 13 Sep rule that a switch is not predictable), and when every other table of the kind is full, or none exists, opens a new table of that boot and category for them. `no_other_table` is left only for a pair the lobby no longer opens. `quickJoin` still takes the fullest. |
| Room code collisions | **Deviation.** Codes are regenerated until unique among live tables. |
| `LOBBY_TABLES` with an unknown category | **Deviation.** Rejected at config load with a clear error (env mode). In db mode (below) a `table_configs` row naming a category this build cannot play is left out with an ERROR and the boot carries on. |
| The table catalogue in PostgreSQL — `TABLE_CONFIG_SOURCE`, `table_engines`/`table_categories`/`table_settings`/`table_configs`, `GET /api/tables`, `session:ready.config.tableConfigVersion`, `/health.tableConfig` (owner, 23 Sep 2026) | **Deviation.** Node composed every table from env keys. Go can read them from four configuration tables instead — engines, categories (foreign keys, so the set stays open), one settings row, one fully resolved row per public table and per private template — ONCE at boot: configuration, never state, so an edit applies after a restart to tables opened after it, and a table restored from Redis whose rules no longer match (or whose pair left the menu) is **drained** — no matchmaking into it (a switch away, or a consolidation of its lone player onto the pair's undrained table or an older drained one of the same rules, may still take players out), `joinCode` still works — rather than changed under its players. `config.GameConfig.Spec` is the one path every table and lobby card is built from; with the seed and in env mode every table plays, and the lobby JSON reads, as before. A bad row is left out with a logged reason; only a catalogue that cannot run a lobby falls back to the env composition (a hand edit must not crash-loop an unrelated restart). Unset, the source is `env` whenever any table key is set, so a `.env` that pins its menu changes nothing until switched on purpose (`ops/DEPLOY.md` §3). In db mode `assertUnderEntryCap` is a no-op: the settings' cap is folded into the table's band, same code and message. A public row's own boot is always an allowed stake (`Validate` appends any `table_settings.stakes` lacks), so a new table is one row. CLAUDE.md §7.3/§7.4 are the reference. |
| Consolidation order and copying chips from the seat | Same as Node. |
| Sweeper interval and the hardcoded 30 s empty-table age | Same as Node; the sweeper uses the injected Clock. |
| A lobby seat or lobby-only wallet change while the wallet still waits for a write from a table (a hand-end settlement the database refused and is retrying, or a destroyed table still settling) | **Deviation (money).** Node had no such wait. A player could leave between hands (a leave that writes nothing) and buy a chip-priced picture, or sit down elsewhere, from a wallet that still held the stake they had lost. The late settlement then clamped the wallet at zero and paid the winner chips that never existed. Go counts, per player, the refused settlements still being retried that move their wallet (`TableOptions.SettlementOwed` → `RoomManager.settlementOwed`). While any is owed, or a destroy is still settling their seat, `room:quickJoin` / `room:joinCode` / `room:create` are refused `settlement_pending` ("Your last hand is still being saved; try again in a moment") and the rewards and a chip-priced picture are answered 409 `seated`. The wait ends when the write lands or its retries are given up. |

## 4. Text handling (chat, names)

| Topic | Decision |
|---|---|
| Length caps (140 chat, 24 names) | Counted in **UTF-16 code units** as Node does, so emoji count as 2. Truncation never splits a surrogate pair: the lone high half is dropped. |
| Stripping `\p{C}` | Strip every rune in Unicode category C (Cc, Cf, Co, Cs) **and** every unassigned rune (no category at all). ZWJ is stripped, as in Node. |
| Whitespace class for collapsing | Go `unicode.IsSpace` **plus** U+FEFF, matching JS `\s`. |
| Non-string `text`/`displayName` on the wire | Numbers are coerced to their decimal string as Node's `String()` does; objects/arrays/booleans/null are treated as empty. |
| Unicode-version differences between V8 and Go tables | Accepted. |
| Display name overwritten on every login (requirement 29) | Same as Node. Known and still unresolved; outside this port's scope. |

| Topic | Decision |

| Unknown `/api/*` path or method | **Deviation.** JSON 404 `{"error":"not_found","message":"Cannot GET /path"}`. Static 404s are plain text. |

| Missiles on the wire and the missile store (owner, 14 Sep 2026) | **Deviation.** Node had no missiles. The public user gains `missile` after `hammer`. Crediting is `db.CreditPurchase`, one transaction under the wallet lock: the chips through the `purchase` chip_ledger row (`gplay:<token>`), then `users.missile += Missiles` and `users.hammer += Hammers` in the same transaction, reached only when that row went in — its UNIQUE action_id is the replay guard for all three, so missiles and hammers need no guard table and never enter `chip_ledger`.
