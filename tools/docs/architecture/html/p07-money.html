FlowsMoney: three checkpoints

PostgreSQL holds the wallet (users.chips) and an append-only audit of every movement (chip_ledger). A bet is not a database transaction, and neither is the deal. The wallet is brought up to date at exactly three moments, each taking that player's chips as the live table has them.

Why it is safe

  • Deltas, never absolutes. Each checkpoint writes seat chips now − chips as last written. A reward or purchase that credited the wallet meanwhile is therefore never overwritten.
  • action_id is UNIQUE, and that is a mechanism. If a settle commits but its answer is lost, the table resends the same request. The replay hits the unique index, the whole transaction rolls back, and the table reads duplicate_action as the success it is. The winner is never paid twice.
  • Resolve once, record twice. A player who packed gets a hand_packed row when the money moves and a zero-delta hand_loss row at the hand end, which records the outcome.
  • The ledger is append-only. A trigger refuses every UPDATE and DELETE on chip_ledger. The one exception is the purge job, which removes hand rows older than ten minutes inside its own guarded transaction.
  • Chips cannot change while seated except at a checkpoint. Every lobby-only wallet change (a chip-priced picture, the Lucky Draw, a reward claim, account deletion) runs under the player's seat stripe and is refused seated at a table. A chip pack bought at a table credits the database and tops up the seat together.
  • The winning tax. At a public Teen Patti table the winner pays their rate on winnings (the pot less their own chips) of 50 Lakh or more. The seat is credited the pot less the tax; the ledger writes the win gross and the tax as its own row, so a hand's rows still sum to zero.
The invariant to keep trueSUM(chip_ledger.delta) per user equals users.chips. Losing Redis loses the hands in play and nothing else: every player keeps what PostgreSQL last knew. Chips can be un-made by an interrupted hand, never created.

FlowsStatistics: Redis first, then one group commit

A player's record (hands played, won and lost, winnings, the winning tax they paid, the hands they held, the variations they played) is not written by the money transactions. Tables record each committed hand's counters in Redis, and a flusher adds them to PostgreSQL in batches, one transaction per batch.

{{svg:stats}}
  1. At the hand's end the table works out a HandStats per player while the cards and rules are still there, and carries them on the settle request.
  2. Only when the ledger's transaction has committed does the table hand them to its StatsRecorder. A replay (duplicate_action) records nothing, so a hand counts at most once.
  3. The recorder queues them off the actor and writes them to Redis: one hash per player, kt:stats:<userId>, one field per counter such as TEEN_PATTI:hands_won or VARIATION:total_tax_paid.
  4. Every STATS_FLUSH_MS (10 s) the flusher moves up to 500 players' counters out atomically under a new batch id.
  5. It adds them in one PostgreSQL transaction: the batch's receipt in stats_flushes first, then one upsert into player_stats and one into player_variation_stats.
  6. Only after the commit is the batch finished in Redis. A crash in between replays the batch, and its receipt makes the replay add nothing.
  7. Every account read sums the player's rows, so the figures trail play by at most one flush interval.
{{code:go-server/internal/stats/flusher.go|Flusher.flush: one batch, one transaction, exactly once (metrics trimmed)}} func (f *Flusher) flush(ctx context.Context, batch live.StatsBatch, report *PassReport) error { deltas := make([]db.StatsDelta, 0, len(batch.Players)) unknown := 0 for userID, fields := range batch.Players { delta, n := Decode(userID, fields) unknown += n deltas = append(deltas, *delta) } sort.Slice(deltas, func(i, j int) bool { return deltas[i].UserID < deltas[j].UserID }) // … a field this build does not know is left out and logged if len(deltas) > 0 { applied, err := f.db.Flush(ctx, batch.ID, deltas) if err != nil { return err // the batch stays taken and is retried under the same id } if applied { report.Batches++ report.Players += len(deltas) } else { // Committed by an earlier attempt whose acknowledgement was lost: // nothing is added twice, and the batch is forgotten now. report.Duplicates++ } } return f.live.FinishStatsBatch(ctx, batch.ID) } {{/code}}

The winning tax a player has paid is their own figure: it is on their account (totalTaxPaid) and in their own Stats drawer, and no other player's profile carries any chip figure.
