ReferenceData model

Two stores with a strict division. PostgreSQL holds what must never be lost: money, accounts, audit and configuration. Redis holds the game being played. No table in PostgreSQL is game state.

ReferenceWire protocol

Realtime traffic is Socket.IO over a websocket at /socket.io/; everything else is REST under /api with a JWT in the Authorization header. Every socket request is acknowledged with {ok: true, …} or {ok: false, code, message}. The full contract is in go-server/PORT_NOTES/specs/spec-socket-protocol.md.

ReferenceDeploy and observe

  • Releases are tags. go-server/vX.Y.Z for the server, flutter-client/vX.Y.Z for the app, bot-play/vX.Y.Z for the bots. ops/build.sh stamps the tag into the binary, and GET /health reports it, so checking what production runs is one curl.
  • One command deploys. ops/deploy.sh <tag> on the host: fetch, check the tag out, build, run the new binary's -migrate before any restart, restart, wait for /health to report the tag, and roll back by itself if it does not.
  • Metrics. GET /metrics exposes every game_* series (sockets, tables, moves, timings, the ledger, the live store, the stats flusher) and the Go runtime. No user id, room id, table code, name or IP is ever a label value.
  • Dashboards and logs. Prometheus, Grafana, Loki and Alloy run on the game host (ops/monitoring/). The server logs JSON lines; a refused login, a refused table write and a table marked draining each have their own line.
  • Tests. go test -race ./... (table rules on a fake clock, database suites on throwaway schemas, real sockets through a test client), the black-box parity suites in tools/parity, and flutter analyze with flutter test.

ReferenceWhere to change things

A rule of Teen Patti
internal/game/table.go; view.go if clients must see it; a test in internal/game on the fake clock.
Hand ranking or a variation
handrank.go, variation.go. One Evaluate; never a second ranking.
Matchmaking, switch, sweeping
internal/game/roommanager.go.
A lobby table or its figures
A row in table_configs (db mode), then a restart. Check with GET /api/tables.
A socket event
internal/socket/wire.go (the payload structs) and handler.go (register it behind guard).
A REST route
internal/auth/http.go (routes) and handlers.go.
Anything that moves chips
internal/db, with a chip_ledger row under a unique action_id; if it is lobby-only, run it inside RoomManager.WhileUnseated.
A table or column
internal/db/migration/V1.0.0__baseline.sql, idempotent; a column twice (CREATE TABLE and a guarded block).
A player statistic
game/stats.go (what a hand counts), stats/codec.go (the Redis field), db/stats.go (the flush and the read).
A metric
internal/metrics/names.go; feed it from the socket layer or a hook, never from game.
A poker rule
internal/poker (hand.go, variant.go, eval5.go).
What the app draws
flutter-client/lib: state/game_state.dart, net/game_connection.dart, screens/, widgets/.
