One Go process runs the whole game. It keeps every table in memory, mirrors each table to Redis after every change, and writes chips to PostgreSQL only at three moments of a hand. Players reach it through nginx; the resident bots sit on the same host and connect over loopback.

The one rule everything followsThe server is the single authority. It shuffles with crypto/rand, deals, checks every bet against a ladder it recomputes itself, decides winners, and sends each player a snapshot with everybody else's cards removed. A client never receives a card or a hidden stack it should not see; it draws snapshots and forwards intent.

ShapeInside the server

The module is go-server/, and its packages form layers. The domain, internal/game, holds the rules and knows nothing about HTTP, SQL or Prometheus. It defines small interfaces for what it needs (a ledger, a live store, a clock, a listener for its events) and the packages around it implement them. internal/app is the only place that knows every piece and wires them together.

{{svg:layers}}
  • Solid arrows are calls. Dashed arrows mean the domain defines an interface and the package below implements it: game.Ledger by db.Ledger, live.Store by Redis or the in-process store, game.StatsRecorder by stats.Recorder.
  • game must not import metrics, db or socket. Metrics reach it as function hooks; the socket layer reaches it as a game.Listener.
  • Nothing but app and cmd imports socket or app.
  • There is no package-level mutable state. Configuration is read once at boot into one immutable config.Config and passed down.
